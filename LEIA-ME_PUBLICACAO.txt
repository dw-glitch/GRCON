GRCON 5.32.0 — PUBLICAÇÃO E PRIMEIRO ACESSO

O QUE MUDA
- Somente documentos ET são pesquisados com e sem NT- no início do 7º grupo.
- Documentos N-1710 continuam sem essa variação.
- Se a outra forma existir na LD, o código e o nome final seguem exatamente a LD.
- O Resumo mostra as duas buscas, a forma encontrada, a alocação, o DE → PARA, o arquivo final e a decisão de inclusão na eGRDT.
- A aba Auditoria detalhada mantém todas as evidências técnicas.
- Relações grandes usam os mesmos módulos e a mesma formatação da análise normal.

VALIDAÇÃO
- Carga automatizada: 15.000 códigos ET, nos dois sentidos da busca.
- Planilhas operacionais usadas em validações manuais não são incluídas nem descritas no repositório público.
- Execute antes de publicar:
    npm ci --ignore-scripts
    npm run verify

PUBLICAÇÃO NA VERCEL
1. A branch publicada é main.
2. Publique todo o conteúdo do repositório, incluindo workers/, package.json e os novos scripts de inicialização.
3. O projeto é estático e não exige etapa de build.
4. Use sempre HTTPS. Login e Service Worker não funcionam por file://.
5. Depois da publicação, confirme no rodapé e na meta application-version a versão 5.32.0.
6. Faça uma recarga completa na primeira abertura. O cache novo é grcon-v5.32.0.

SUPABASE — ORDEM DAS MIGRAÇÕES PARA UMA BASE EXISTENTE
1. Confirme que as migrações 5.31.4, 5.31.5, 5.31.6, 5.31.7, 5.31.8, 5.31.9, 5.31.10 e 5.31.14 já foram aplicadas conforme o histórico do projeto.
2. Aplique SUPABASE_MIGRACAO_5.32.0.sql.
3. Execute os Advisors de Security e Performance.
4. Consulte SUPABASE_AUDITORIA.md para as limitações e o checklist.

ATENÇÃO PARA INSTALAÇÃO EM OUTRO PROJETO
- SUPABASE_MIGRACAO_5.31.10.sql é um registro resumido de uma migração já aplicada e não contém os corpos completos de duas funções privadas.
- Recupere o SQL integral do histórico do projeto Supabase antes de tentar reconstruir uma base nova.
- Não aplique migrações de produção sem backup e conferência do projeto correto.
